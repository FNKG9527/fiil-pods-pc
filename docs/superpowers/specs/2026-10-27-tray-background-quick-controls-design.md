# FiilPods PC 系统托盘后台与快捷切换设计

- 日期：2026-10-27
- 状态：已确认方案，待书面设计确认
- 范围：现有 `app.py` / `ble_worker.py` 桌面应用，不修改 FIIL 协议命令

## 1. 目标与验收

在 Windows 上把现有控制台变成可驻留系统托盘的桌面软件：

1. 主窗口右上角 × 默认隐藏到托盘，不结束进程，也不主动断开 BLE。
2. 双击托盘图标显示并置顶已有主窗口；右键菜单也可显示/隐藏窗口。
3. 右键菜单可直接切换所有已有语义化控制：MAF 五档、低延迟、影院、畅连、提示音量四档。
4. 托盘命令必须复用现有 `BleWorker` 队列和原窗口动作；ACK、错误、读回校验、日志和主窗口状态继续生效。
5. 托盘「退出」才停止 worker、移除图标并退出进程。
6. 托盘不可用时仍保留原窗口应用能力，并明确提示，不静默退出或假装后台成功。

非目标：全局快捷键、开机自启、自动连接、独立 Windows 服务、未经验证的新协议命令、EQ 快捷控制、播放器控制、重写现有 GUI。

## 2. 已确认方案与备选

采用完整系统托盘方案，而非仅隐藏窗口的简化方案，也不引入第二个后台进程。

选择依据：当前 BLE worker 由 Tk 主线程持有，事件已经通过队列跨线程传递；在同一进程增加托盘，能够直接复用窗口动作、状态和连接生命周期。独立服务会造成状态同步、安装和排错的额外复杂度，不符合本次需求。

## 3. 组件与职责

### `quick_controls.py`：共享快捷控制定义

定义唯一的控制项目录：稳定动作 ID、分组、显示名称、协议值、是否只在 GAIA 四档机型显示。主窗口按钮生成与托盘菜单都消费同一份定义，避免两套命令或标签漂移。

提供无 Tk、无 BLE 依赖的菜单模型函数：输入只读状态快照，返回菜单项、当前勾选态和可用性。MAF 和低延迟采用互斥单选，影院与畅连采用布尔切换，提示音量采用互斥单选。低延迟 2/3 只有在状态表明机型支持时显示，沿用现有 `_ensure_ll_buttons()` 的规则。

### `tray_support.py`：可选依赖与托盘适配

检测并延迟导入 `pystray` 和 `Pillow`。生产环境优先使用 `pystray`，由它处理 Windows 通知区图标和菜单；使用现有 `build/app.ico` 作为托盘图标。

托盘库产生的回调不得直接操作 Tk 控件。所有窗口调用都通过一个主线程调度接口执行；BLE 请求仍进入现有 `Command` 队列。托盘退出使用同一个幂等关闭流程，避免 Tk 已销毁后回调报错。

模块导入不得因为缺少托盘依赖而使 `app.py` 启动失败。源码运行缺少依赖时禁用「最小化到托盘」并提示安装命令；正式 EXE 必须将依赖和图标打入包内。

### `app.py`：窗口生命周期与统一动作

新增薄协调层，负责：

- 创建/销毁托盘，记录窗口是否隐藏及是否正在退出。
- `show_window()`：在 Tk 主线程 `deiconify`、`lift`、必要时 `focus_force`；重复调用安全。
- `hide_to_tray()`：托盘可用时 `withdraw`，进程与 BLE worker 保持运行；不可用时显示警告并保持窗口可见。
- `toggle_window()`：依据窗口真实状态显示或隐藏。
- `request_exit()`：只执行一次，先停止接受新托盘操作，再移除托盘、关闭 worker、销毁 Tk。
- 提供线程安全的主线程调度方法；所有 Tk 读取和写入只能在主线程执行。

把托盘动作映射到现有 `_on_set_maf()`、`_on_set_low_latency()`、`_on_set_cinema()`、`_on_set_multipoint()`、`_on_set_tone()` 等入口。对于当前由 Checkbutton 变量驱动的布尔动作，协调层先按菜单目标值设置变量，再调用原回调，不另发协议帧。

现有 `_on_refresh_all()`、连接和断开入口同样复用。主窗口的 × 绑定到 `hide_to_tray()`；原 `_on_close()` 的真实退出语义改由统一 `request_exit()` 提供。

### 打包与安装

`requirements.txt` 增加 Windows 托盘运行依赖；PyInstaller spec 收集 `pystray` 所需模块。安装程序与目录版继续包含 `app.ico`。Inno Setup 可选增加开机启动项不在本次范围，不改变现有安装权限和卸载流程。

## 4. 菜单结构

- 显示/隐藏主窗口（默认项，双击等效于显示）
- 状态：未连接 / 已连接 / 切换中（只读）
- 连接 / 断开 / 刷新全部状态
- 降噪模式：关闭、降噪、开放、兼听、风中
- 低延迟：关闭、开启（游戏）；GAIA 机型补充音乐、视频
- 影院模式：开、关
- 蓝牙畅连：开、关
- 语音提示音量：高、中、低、静音
- 退出

菜单显示状态为最近一次已知快照，不把它当作实时硬件事实；以 ACK 与后续读回为最终依据。未连接或操作正在切换时，相关项禁用或给出清晰提示，不能显示虚假成功。

## 5. 数据流与线程规则

托盘动作 → 主线程调度 → 现有 App 动作 → `cmd_q` → `BleWorker` → `evt_q` → 现有 `_pump()` / `_handle_event()` → Tk 状态与日志。

从 BLE 事件派生一个小的只读状态快照，供托盘菜单更新。快照至少包括连接状态、MAF、低延迟、影院、畅连、提示音量，以及最近操作结果。不得在托盘线程读取 `tk.StringVar` 或直接更新 Tk。

托盘菜单在显示前或状态变更后重建/刷新，避免勾选状态滞后。打开菜单时不需要发起一轮硬件读取；连接后原有握手及「刷新全部状态」负责填充状态。

## 6. 关闭与异常路径

- ×：隐藏窗口；如果托盘初始化失败，保留窗口并显示一次性说明。
- 托盘退出、主线程退出、worker 异常终止：经同一幂等退出函数，保证图标不残留、BLE worker 被通知关闭。
- Windows Explorer 重启导致图标消失：若所选库支持则依赖其重建；本次不自行实现 Explorer 监视器。
- 蓝牙断开：保留托盘，状态显示未连接；控制项不可执行，用户仍可恢复窗口重连。
- 畅连切换：沿用固件主动断开与 worker 自动重连流程，不新增独立重连逻辑。
- 命令被拒绝或读回不符：沿用现有状态栏/日志提示，并在托盘状态摘要中可见；不弹「成功」通知。

## 7. 测试策略

严格先写失败测试，再写实现，逐一验证 Red → Green → Refactor。

### 离线自动测试

- 共享控制目录：所有动作 ID 唯一，协议值与 `MafMode`、`LowLatencyMode`、`ToneVolume` 一致。
- 菜单模型：MAF/低延迟/提示音量互斥勾选，影院/畅连布尔值，GAIA 低延迟档位条件显示，未连接禁用。
- 线程调度：模拟托盘线程提交回调，断言只在 Tk 主线程执行，异常被记录而不破坏事件泵。
- 窗口生命周期：用伪 root/托盘/worker 验证 × 只隐藏、双击恢复、重复恢复安全、退出只调用一次 worker.shutdown 和托盘移除。
- 命令映射：伪 App 验证每个托盘动作调用现有动作及正确参数，布尔动作用目标值而不是盲目翻转。
- 无托盘库时：模拟导入失败，原窗口仍能创建，隐藏请求有可见回退。
- 运行原 5 个离线测试与 `ruff check .`，防止协议及现有 worker 回归。

### Windows 实际验证

启动源码和冻结 EXE，检查：托盘图标存在、右键全分组、× 后进程与连接存活、双击恢复、未连接提示、退出后无进程/图标残留。若当前沙箱禁止通知区写入或真机不可用，明确区分环境阻塞与代码结果，不宣称未执行的硬件验证已通过。
